If setup appears on an established installation, stop and verify that Processor is connected to the intended database volume.

## Purpose

Authentication protects application pages and GraphQL operations. Credentials establish a server-side session whose role is enforced by route and resolver authorization.

## Prerequisites and permissions

Set a strong `NEXTAUTH_SECRET`, configure the canonical application URL, and create the first admin. Any active user can sign in; only admins can create or manage other users.

## Normal workflow

1. Enter the account email and password.
2. Complete sign-in and confirm the dashboard loads.
3. Use Profile to rotate your password or change language.
4. Sign out when using a shared device.

## Important controls and behavior

- Passwords are hashed before storage and are never returned through GraphQL.
- Authorization is checked on the server; hiding a UI control is not the security boundary.
- Locale-prefixed routes preserve the selected application language.
- The first-user setup flow closes after successful account creation.

## Failure states

Invalid credentials return a generic error. Repeated session failures often indicate an inconsistent secret, incorrect public URL, proxy cookie handling, or clock skew. A locked-out single-admin installation requires an operator-controlled database recovery rather than reopening setup.

## Operational notes

Rotate secrets through the deployment platform and restart all instances together. Changing `NEXTAUTH_SECRET` invalidates existing sessions.
